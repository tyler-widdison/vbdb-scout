## Assistant (Plan · GLM-5.1 · 30.5s)

Found the root causes. Two problems after batch upload:

### Problem 1: New seasons aren't visible

When `auto_season=true`, the Rust backend creates new seasons (e.g. "2024", "2025"). But the frontend's `seasons` and `selectedSeasonIds` are stale — they were loaded at init. `SeasonTree.refresh()` only queries matches for the *currently selected* season IDs, which don't include the new ones.

### Problem 2: Only one tree refreshes

When uploading from `MatchEmptyState` (SeasonsView), only SeasonsView's `SeasonTree` gets `refresh()` called. The HomeView's `SeasonTree` and its teams list remain stale.

### Fix plan

**1. After import, reload seasons + update selection:**

Both upload paths (SeasonTree's button and MatchEmptyState) need to, after import:
```
await reloadSeasons()                    // fetch new seasons from DB
setSelectedSeasons(all visible season IDs) // select all for current association
```

**2. Use a DOM event for cross-component refresh:**

After import completes, dispatch `window.dispatchEvent(new CustomEvent("scout-files-imported"))`. Listeners:
- **HomeView**: re-fetch teams via `getTeamsForSeasons`
- **SeasonTree** (both instances): call `refresh()` on mount + listen for event

**3. Implementation:**

| Component | Change |
|---|---|
| `MatchEmptyState.vue` | After `importScoutFiles`, dispatch `"scout-files-imported"` event |
| `SeasonTree.vue` | After own `uploadMatches`, dispatch same event + call `reloadSeasons` from context |
| `HomeView.vue` | Listen for `"scout-files-imported"` → re-fetch teams |
| `useExplorerContext.ts` | Expose a `refreshAfterImport()` helper that reloads seasons + selects all visible ones |

This way any upload from anywhere triggers a full refresh everywhere. Want me to proceed?
